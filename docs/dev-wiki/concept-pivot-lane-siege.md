# 컨셉 전환 초안: 던전 스쿼드 액션 -> 모바일 레인 공성/고용 전략

## 왜 새 문서가 필요한가

현재 프로토타입은 **리더 1기 + 추종 병력**을 끌고 던전을 돌며 자동전투와
리더 스킬을 쓰는 구조다. 하지만 사용자 의도는 이제 훨씬 더 분명하다:

- LoL / DotA처럼 **양 진영 스타팅 포인트가 있는 레인 기반 대칭 전장**
- Civilization Wars 계열처럼 **기술 해금 / 병종 오픈 / 업그레이드 / 자동
  진군 유닛**이 핵심
- 플레이어는 단일 영웅을 직접 싸우게 하는 것이 아니라, **깃발 든 리더가
  고용/건설/기술 해금/전선 관리**를 수행하는 존재
- 모바일 조작 기준으로 단순하지만, 경제와 운영의 의사결정은 깊어야 함

즉, 현재 게임은 "전투 액션 로그라이트"이고, 목표 게임은
"모바일 레인 공성 운영 RTS-lite"에 더 가깝다.

## 외부 참고에서 뽑은 핵심

### 1. LoL / Wild Rift에서 가져올 구조

출처:

- Riot 공식 LoL How to Play  
  https://www.leagueoflegends.com/en-us/how-to-play/
- Riot 공식 Wild Rift Overview  
  https://wildrift.leagueoflegends.com/en-sg/game-overview/

핵심:

- 양 팀은 **자기 기지와 적 기지**를 두고 싸운다.
- 목표는 적 본진 핵심 건물을 파괴하는 것이다.
- 기지에서 **미니언이 생성**되고 레인을 따라 전진한다.
- 레인에는 **방어 구조물(터렛 등)** 이 있어 미니언이 먼저 맞아줘야 안전하게
  전진할 수 있다.
- 모바일 버전(Wild Rift)은 원작 구조를 유지하되 **더 빠른 템포와 단순한
  입력**으로 압축했다.

이 문서에서의 해석:

- 우리는 "챔피언 스킬샷 MOBA"를 만들려는 것이 아니라,
  **레인-기지-자동 전선 압박**이라는 큰 구조를 가져오려는 것이다.

### 2. DotA 계열에서 가져올 구조

출처:

- Defense of the Ancients 개요  
  https://en.wikipedia.org/wiki/Defense_of_the_Ancients
- Dota 2 Wiki - Lane  
  https://dota2.fandom.com/wiki/Lane

핵심:

- 반대편 코너의 두 기지
- 그 사이를 잇는 **복수 레인**
- **AI-controlled creeps** 가 주기적으로 생성되어 밀고 당기는 전선을 형성
- 플레이어는 그 위에서 전장 영향력을 행사한다

이 문서에서의 해석:

- 사용자가 원하는 건 "영웅 대전" 자체보다도
  **자동 생성 병력이 충돌하며 전선을 형성하는 감각**이다.
- 따라서 플레이어 캐릭터는 딜러 주체가 아니라
  **전선 관리자 + 현장 작업반 리더**로 재해석하는 편이 맞다.

### 3. Civilization Wars에서 가져올 구조

출처:

- The Helper 포럼 소개글  
  https://www.thehelper.net/threads/civilization-wars.34131/
- 검색 결과 요약(Hive/영상 메타데이터 포함)

핵심:

- 자동 생성 유닛들이 상대편으로 밀고 들어간다.
- 중간 자원 거점이 전황을 바꾼다.
- 거의 40개 수준의 **기술 연구**가 새 유닛/보너스/구조물/가능성을 연다.
- 시대가 올라가며 병종이 바뀌고, 팀 전체 운영 감각이 변한다.

이 문서에서의 해석:

- 이번 피벗에서 가장 중요한 차별점은 바로 이것이다:
  **"내 캐릭터가 직접 싸우는 게임"이 아니라 "내 운영이 싸움을 만든다"**.

## 사용자 의도를 바탕으로 정리한 새 게임 기둥

아래는 외부 참고 + 사용자 요구를 결합한 **목표 구조**다.

### 1. 경기 구조

- 최대 4인 참가
- 맵 네 귀퉁이에 각 진영 시작 본진 배치
- 본진 간을 잇는 레인 또는 연결 전선 존재
- 승리 조건:
  - 최종안 A: 적 본진 파괴
  - 최종안 B: 적 본진 코어/깃발 파괴

현재로서는 **A가 구현 단순성 면에서 더 낫다**.

### 2. 플레이어 역할

- 플레이어는 검/활/마법 영웅을 직접 조작하는 주체가 아니다.
- 플레이어가 조작하는 것은 **깃발 든 리더 유닛**이다.
- 리더는 다음 행동을 담당한다:
  - 병력 고용
  - 거점/요새 건설
  - 본진 복귀 후 기술 해금 및 업그레이드
  - 전선에 명령/버프/긴급 스킬 사용

즉, 리더는 전투 영웅보다 **현장 지휘관 + 공병 + 구매 담당**에 가깝다.

### 3. 병력 생산/유지

- 병력은 돈을 내고 **한 명씩 고용**
- 고용된 병력은 일정 시간마다 **급여(maintenance wage)** 로 금을 소모
- 유지비 때문에 무작정 병력을 늘릴 수 없음
- 병종 오픈과 무기 업그레이드에 따라 고용 가능한 유닛이 확장

이 시스템의 장점:

- 초반에는 "적은 수의 값싼 병력" 운영
- 중반에는 "유지비를 감당하며 전선 밀기"
- 후반에는 "고급 병종 vs 경제 압박" 판단이 생김

### 4. 자동 전선

- 고용/생성된 병력은 레인을 따라 자동 전진
- 적 병력/요새/본진을 만나면 자동 전투
- 플레이어는 병력을 직접 낱개 조종하지 않음
- 대신 다음으로 영향력 행사:
  - 병종 구성
  - 업그레이드
  - 생산/고용 타이밍
  - 건설 위치
  - 리더 현장 지원 스킬

### 5. 거점과 요새

- 레인 중간중간 **점령 가능한 거점** 배치
- 거점 기능 예시:
  - 금 수입 증가
  - 전선 보급
  - 병력 리스폰/재합류 단축
  - 방어 건물 건설 가능
- 리더가 해당 위치에 가서 **요새/보루/화살탑/보급소** 등을 직접 건설

### 6. 기술 해금 / 업그레이드

- 본진에서만 가능한 기술 트리
- 연구 항목 예시:
  - 시대 상승
  - 근접 무기 강화
  - 활/투사체 강화
  - 방어구 강화
  - 특정 병종 해금
  - 요새 건설 해금
  - 급여 효율/세금 개선

중요:

- 사용자 설명상 기술 해금은 단순 레벨업 보상이 아니라
  **경제 행동의 결과**여야 한다.

## 현재 프로토타입에서 살릴 것 / 버릴 것

### 살릴 것

- 등각 렌더링 파이프라인
- 모바일 친화 입력 기준
- HUD 아트 톤
- 카메라/미니맵 기본 프레임
- 리더 시각 정체성(깃발)
- 개별 유닛 단위 렌더링 및 HP bar 시스템 일부

### 거의 버려야 할 것

- 던전 절차 생성
- 포로 구출 중심 루프
- 현재의 3슬롯 액티브 스킬 구매/장착 흐름
- 인벤토리/마나 포션 중심 설계
- "적 AI가 플레이어 스쿼드를 추적해서 싸우는" 현재 전투 로직
- 로그라이트 한 판 탐험 구조

### 재해석해서 살릴 수 있는 것

- `Squad` 개념 -> `ArmyRoster` 또는 `ControlledForce`
- `leaderLevelPoints` -> 기술 포인트나 명성/사령 경험치로 전환 가능
- `DungeonScene`의 직교 물리 + 등각 시각 분리 패턴 -> 레인 전장에도 유용

## 내부 구현을 어떻게 갈아엎어야 하나

아래는 **지금 코드 기준 실제 변경 단위**다.

### 1. 맵 시스템 교체

현재:

- `generateDungeon()` 기반 랜덤 던전

필요:

- 고정형 또는 시드형 **대칭 레인 전장 생성기**
- 2인/4인 모드에 따라 다른 레이아웃 지원
- 요소:
  - 본진
  - 레인
  - 교차 광장
  - 거점
  - 건설 가능 구역

추천 새 파일:

- `src/systems/battlefieldGenerator.ts`
- `src/data/maps.ts`

### 2. 스쿼드 시스템 재구성

현재:

- 리더 + 추종 병사 + 개별 HP/XP

필요:

- 고용 병력 목록
- 병종별 비용 / 유지비 / 전선 배치 상태
- 자동 스폰 또는 리더 동행 병력의 구분
- 병력 소속, 레인 배치, 목적지 상태

추천 방향:

- `Squad`를 유지보수하기보다 `ArmySystem`으로 교체하는 편이 깔끔함.

### 3. 경제 시스템 신설

필수 새 시스템:

- `gold`
- `income per tick`
- `wage per tick`
- `capture income`
- `tech cost`
- `build cost`
- `recruit cost`

추천 새 파일:

- `src/systems/economy.ts`

### 4. 기술 트리 시스템 신설

필수 기능:

- 연구 가능한 항목 데이터
- 선행 조건
- 연구 시간 또는 즉시 구매 여부
- 연구 결과:
  - 병종 해금
  - 능력치 업그레이드
  - 구조물 해금
  - 경제 보너스

추천 새 파일:

- `src/data/techTree.ts`
- `src/systems/research.ts`

### 5. 구조물/거점 시스템 신설

필수 기능:

- 본진
- 거점
- 요새
- 화살탑
- 보급소
- 파괴/점령 상태

추천 새 파일:

- `src/data/structures.ts`
- `src/systems/structures.ts`

### 6. 전투 시스템 단순화 + 대규모 유닛 대응

현재 전투는 소수 정예 스쿼드 기준이다. 새 게임은 병력이 더 많아질 수 있으므로:

- 개별 유닛 고급 AI보다
- **레인 이동 + 근거리 충돌 + 간단 표적 선택 + 집단 DPS 계산**
  쪽이 더 적합할 가능성이 크다.

중요:

- 모바일에서 다수 유닛을 안정적으로 돌리려면
  "정교한 1:1 액션 전투"보다
  **간결한 시뮬레이션형 전투**가 성능과 가독성에 유리하다.

### 7. UI 재설계

현재 UI는 "스킬 슬롯 + 인벤토리"다.

새 UI는 아래처럼 바뀌어야 한다:

- 좌측 또는 하단:
  - 금
  - 수입
  - 유지비
  - 인구/병력 수
- 우측 패널:
  - 고용 탭
  - 건설 탭
  - 연구 탭
  - 리더 명령 탭
- 리더 근처 컨텍스트 UI:
  - 본진 접근 시 연구/업그레이드 열기
  - 거점 접근 시 건설 메뉴 열기

## 구현 순서 제안

### Phase 0. 컨셉 확정

- 2인부터 시작할지, 4인까지 한 번에 갈지
- 레인 수를 1/2/3 중 무엇으로 할지
- 리더가 병력을 데리고 직접 이동하는지, 아니면 본진-거점 사이만 다니는지

### Phase 1. 맵/전장 뼈대

- 던전 제거
- 대칭 전장 배치
- 본진/거점/레인 표시
- 카메라/미니맵 재작업

### Phase 2. 경제/고용 루프

- 금 수급
- 병력 고용
- 유지비 차감
- 자동 전진

### Phase 3. 구조물/거점

- 점령
- 건설
- 방어 구조물 공격

### Phase 4. 기술 트리

- 병종 해금
- 업그레이드
- 시대 변화 연출

### Phase 5. 리더 액션과 모바일 UX

- 본진 상호작용
- 거점 건설 상호작용
- 빠른 명령 버튼

## 지금 단계에서의 권장 결론

현재 프로토타입 위에 "조금 수정"으로는 안 된다.  
**게임의 중심 루프가 바뀌기 때문에, 사실상 새 코어를 세우는 수준의
피벗**으로 보는 게 맞다.

다만 완전 폐기는 아니다.

- 비주얼 톤
- 등각 표시 방식
- 일부 유닛 렌더링
- 모바일 UI 방향성

은 다음 게임으로 그대로 이관 가능하다.

## 다음 상담에서 꼭 결정해야 할 질문

1. 2인 대전부터 만들지, 처음부터 4인 자유전까지 넣을지
2. 레인은 1개 / 2개 / 3개 중 몇 개로 시작할지
3. 리더는 "전장 순회형"인지, "본진/거점 작업형"인지
4. 병력은 본진에서 자동 생성되는지, 리더가 직접 고용해야만 나오는지
5. 기술 업그레이드는 즉시 구매식인지, 연구 시간 방식인지
6. 거점은 점령 즉시 수입을 주는지, 건설 후 활성화인지
7. 초반 MVP 승리 조건은 본진 파괴 하나로 충분한지
