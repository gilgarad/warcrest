# 컨셉 전환 초안: 던전 스쿼드 액션 -> 모바일 레인 공성/고용 전략

## 왜 새 문서가 필요한가

현재 프로토타입은 **리더 1기 + 추종 병력**을 끌고 던전을 돌며 자동전투와
리더 스킬을 쓰는 구조다. 하지만 사용자 의도는 이제 훨씬 더 분명하다:

- LoL / DotA처럼 **양 진영 스타팅 포인트가 있는 레인 기반 대칭 전장**
- Civilization Wars 계열처럼 **기술 해금 / 병종 오픈 / 업그레이드 / 자동
  진군 유닛**이 핵심
- 플레이어는 단일 영웅을 직접 싸우게 하는 것이 아니라,
  **전선/경제/연구/건설을 관리하는 운영 주체**
- 모바일 조작 기준으로 단순하지만, 경제와 운영의 의사결정은 깊어야 함

즉, 현재 게임은 "전투 액션 로그라이트"이고, 목표 게임은
"모바일 레인 공성 운영 RTS-lite"에 더 가깝다.

## 외부 참고에서 뽑은 핵심

### 1. LoL / Wild Rift에서 가져올 구조

출처:

- Riot 공식 LoL How to Play  
  https://www.leagueoflegends.com/en-us/how-to-play/
- Riot 공식 Wild Rift Overview  
  https://wildrift.leagueoflegends.com/en-sg/game-overview/

핵심:

- 양 팀은 **자기 기지와 적 기지**를 두고 싸운다.
- 목표는 적 본진 핵심 건물을 파괴하는 것이다.
- 기지에서 **미니언이 생성**되고 레인을 따라 전진한다.
- 레인에는 **방어 구조물(터렛 등)** 이 있어 미니언이 먼저 맞아줘야 안전하게
  전진할 수 있다.
- 모바일 버전(Wild Rift)은 원작 구조를 유지하되 **더 빠른 템포와 단순한
  입력**으로 압축했다.

이 문서에서의 해석:

- 우리는 "챔피언 스킬샷 MOBA"를 만들려는 것이 아니라,
  **레인-기지-자동 전선 압박**이라는 큰 구조를 가져오려는 것이다.

### 2. DotA 계열에서 가져올 구조

출처:

- Defense of the Ancients 개요  
  https://en.wikipedia.org/wiki/Defense_of_the_Ancients
- Dota 2 Wiki - Lane  
  https://dota2.fandom.com/wiki/Lane

핵심:

- 반대편 코너의 두 기지
- 그 사이를 잇는 **복수 레인**
- **AI-controlled creeps** 가 주기적으로 생성되어 밀고 당기는 전선을 형성
- 플레이어는 그 위에서 전장 영향력을 행사한다

이 문서에서의 해석:

- 사용자가 원하는 건 "영웅 대전" 자체보다도
  **자동 생성 병력이 충돌하며 전선을 형성하는 감각**이다.
- 따라서 플레이어 캐릭터는 딜러 주체가 아니라
  **전선 관리자 + 현장 작업반 리더**로 재해석하는 편이 맞다.

### 3. Civilization Wars에서 가져올 구조

출처:

- The Helper 포럼 소개글  
  https://www.thehelper.net/threads/civilization-wars.34131/
- 검색 결과 요약(Hive/영상 메타데이터 포함)

핵심:

- 자동 생성 유닛들이 상대편으로 밀고 들어간다.
- 중간 자원 거점이 전황을 바꾼다.
- 거의 40개 수준의 **기술 연구**가 새 유닛/보너스/구조물/가능성을 연다.
- 시대가 올라가며 병종이 바뀌고, 팀 전체 운영 감각이 변한다.

이 문서에서의 해석:

- 이번 피벗에서 가장 중요한 차별점은 바로 이것이다:
  **"내 캐릭터가 직접 싸우는 게임"이 아니라 "내 운영이 싸움을 만든다"**.

## 사용자 의도를 바탕으로 정리한 새 게임 기둥

아래는 외부 참고 + 사용자 요구를 결합한 **목표 구조**다.

### 1. 경기 구조

- 현재 MVP는 **1:1 PvE/PvP 확장형 구조**로 시작:
  - 당장은 **플레이어 1명 vs 컴퓨터 1명**
  - 추후 인터넷 멀티 기준으로 2인 이상 플레이 가능하게 확장
- 최종 확장 목표는 최대 4인 참가
- 맵 네 귀퉁이에 각 진영 시작 본진 배치 가능
- 본진 간을 잇는 레인 또는 연결 전선 존재
- 승리 조건:
  - 최종안 A: 적 본진 파괴
  - 최종안 B: 적 본진 코어/깃발 파괴

현재로서는 **A가 구현 단순성 면에서 더 낫다**.

### 1-1. 레인 구조 결정

- **1:1 기본형은 레인 1개**로 시작
- 다인전 확장 시:
  - 한 유저가 나머지 세 유저에게 연결되는 레인을 가질 수 있음
  - 즉, "모든 모드가 LoL식 3레인"이 아니라
    **상대 수에 따라 연결선이 늘어나는 그래프형 레인 구조**에 더 가까움

이 결정은 중요하다:

- 현재부터 맵 시스템을 "복수 고정 레인 MOBA 복제"로 짜면 안 되고
- **노드(본진/거점) + 연결선(레인)** 구조로 짜야 나중 확장이 쉬움

### 2. 플레이어 역할

- **돌아다니는 플레이어 캐릭터는 없다.**
- 플레이어는 다음 운영 행위를 담당한다:
  - 본진 광장에서 시대/연구/산업 관리
  - 자기 미니언 path와 거점 기반 건설 선택
  - 거점 건물 터치 후 업그레이드/변경
  - 인구(일꾼)를 산업 시설에 배치

즉, 플레이어는 액션 영웅이 아니라 **운영자/사령관**이다.

### 3. 병력 생산/유지

- **미니언 기본 생산은 자동**
- **방향별 path마다 미니언은 무조건 생성**
- 자동 생성 미니언은 다음에 따라 달라진다:
  - 현재 시대
  - 유저 업그레이드 상황
  - 유저가 선택한 신시대/구시대 조합 설정
- 병종 오픈과 무기 업그레이드에 따라 생산 가능한 유닛풀이 확장
- 별도의 상시 유지 전력/특수 유닛/수비대가 존재한다면 유지비 시스템을
  붙일 수 있음

이 시스템의 장점:

- 초반에는 단순 자동 생산 위주
- 중반에는 시대 변화와 병종 조합 선택이 핵심
- 후반에는 신시대 강제 전환 타이밍과 연구 격차가 승부를 가름

### 3-1. 시대 전환과 병종 조합 규칙

- 시간과 기본 레벨 상승에 따라 유저는 새로운 시대에 도달
- 새 시대에 들어가면 기본 유닛군이 달라짐
- 한동안은:
  - **새 시대 기본 유닛**
  - **구시대 업그레이드 유닛**
  을 섞는 조합을 플레이어가 바꿀 수 있음
- 단, **모든 유저가 같은 시대에 진입한 뒤**,
  **가장 마지막으로 그 시대에 들어온 유저의 진입 시점 이후 n분**이 지나면
  더 이상 조합 변경 불가
- 그 이후에는 **무조건 새 시대 유닛만 생산**

### 4. 자동 전선

- 고용/생성된 병력은 레인을 따라 자동 전진
- 적 병력/요새/본진을 만나면 자동 전투
- 플레이어는 병력을 직접 낱개 조종하지 않음
- 대신 다음으로 영향력 행사:
  - 병종 구성
  - 업그레이드
  - 생산/고용 타이밍
  - 건설 위치
  - 리더 현장 지원 스킬

### 5. 거점과 요새

- 레인 중간중간 **점령 가능한 거점** 배치
- 거점 기능 예시:
  - 금 수입 증가
  - 전선 보급
  - 병력 리스폰/재합류 단축
  - 방어 건물 건설 가능
- 자기 미니언이 통과한 거점 포인트에서 **요새/보루/화살탑/병참기지** 등을
  건설 가능
- 건설 가능한 종류는 거점 종류/시대/기술 해금 상태에 따라 달라짐
- 건물은 기본적으로 금과 각종 자원을 요구

### 6. 기술 해금 / 업그레이드

- 본진에서만 가능한 기술 트리
- 연구 항목 예시:
  - 시대 상승
  - 근접 무기 강화
  - 활/투사체 강화
  - 방어구 강화
  - 특정 병종 해금
  - 요새 건설 해금
  - 급여 효율/세금 개선

중요:

- 사용자 설명상 기술 해금은 단순 레벨업 보상이 아니라
  **경제 행동의 결과**여야 한다.

### 6-1. 연구소/산업시설 규칙

- 플레이어는 본진에서 **시대별 연구시설/산업시설**을 건설
- 시대가 변하면 연구시설은 새 시대 연구소로 업그레이드
- 특정 시대에 반드시 존재해야 하는 산업 계통이 있음
  - 예: 근대인데 화약 생산 연구소가 전혀 없으면 안 됨
- 따라서:
  - 이전 시대부터 해당 계통 연구소를 꾸준히 운영한 유저는
    새 시대 진입 시 일정 수준 **자동 업그레이드 이점**을 얻음
  - 해당 계통이 전혀 없는 유저가 새 시대에 도달하면
    시스템이 최소 기능의 **기본 연구소를 자동 보급**할 수 있음

### 6-2. 인구/노동 배치

- 본진 광장에서 시대와 상황에 따라 **인구(일꾼)** 가 증가
- 플레이어는 이 인구를 각 산업 현장에 배치
- 자원 축 초안:
  - 금
  - 목재
  - 식량
  - 화약(흑연 -> 무연)
  - 연료(석탄 -> 오일)
  - 금속(석기 -> 동 -> 청동 -> 철 -> 강철 -> 합금)
- **MVP에서 실제로 활성화할 자원은 다음 4종으로 고정**
  - 금
  - 목재
  - 식량
  - 금속
- 화약/연료는 초반 MVP에선 비활성 상태로 두고,
  데이터/코드 구조상 나중에 붙여넣기 쉽게 설계
- 어떤 자원이든 **인구 1당 기본적으로 10초에 1** 생성하는 것을 기본 규칙으로 둠
- 즉, 경제 핵심은 "어느 자원 라인에 인구를 얼마나 배치하느냐"가 됨

### 6-3. 초기 고용/운영 비용 감각

- 기본 고용 조건 초안:
  - 금 10
  - 목재 10
  - 식량 10
- **일꾼 1 고용**의 초기 비용도 위와 동일:
  - 금 10
  - 목재 10
  - 식량 10
- 이 뜻은 초반부터 단일 자원 누적이 아니라
  **기본 3자원 균형**이 맞아야 전력을 늘릴 수 있다는 것
- 장기적으로는:
  - 병력 고용
  - 병종 업그레이드
  - 연구소/산업시설 건설
  - 거점 건물 건설
  모두가 자원 분배 효율에 걸리게 됨

### 6-4. 확장 가능한 자원/시대 구조 원칙

- MVP는 4자원만 켜더라도, 데이터 구조는 처음부터
  **"자원 종류 추가"가 쉬운 형태**여야 함
- 즉, 코드/소스 구조는 다음을 전제로 설계:
  - 자원 enum 고정 하드코딩 최소화
  - 건물/연구/유닛 비용은 자원 맵 형태로 표현
  - 시대별 자원 활성/비활성 상태를 데이터로 제어
  - 화약/연료 같은 후반 자원은 코드 분기보다 데이터 추가로 붙일 수 있어야 함

추천 구조:

- `src/data/resources.ts`
  - 자원 ID, 표시명, 시대 해금 조건, 아이콘 키
- `src/data/ages.ts`
  - 시대 정의, 기본 생산 유닛군, 활성 자원, 연구소 변화
- `src/data/unitRosters.ts`
  - 시대별 기본 유닛군 + 구시대 혼합 허용 후보
- `src/data/costs.ts` 또는 각 데이터 안의 `cost: Partial<Record<ResourceId, number>>`
  - 고용/연구/건설/업그레이드 비용 표현

### 6-5. 식량과 보급대 규칙

- 식량은 단순 자원이 아니라 **출전 유지 자원** 성격을 가짐
- 미니언이 웨이브로 출전할 때마다 식량이 일정량 감소
- 각 웨이브에는 **보급대 미니언**이 함께 출전
- 보급대 미니언의 역할:
  - 전열 뒤에서 아군 미니언 회복
  - 시대마다 다르지만, 해당 웨이브에 출전한 미니언 수를 커버 가능한 수준
- 보급대 미니언이 사망하면:
  - 해당 전선 미니언들의 공격력/방어력이 시간이 지나며 점점 감소
- 단, 이후 웨이브의 보급대와 합류하면:
  - 기존 전선 미니언을 다시 회복/지원 가능

이 규칙의 의미:

- 식량은 "있으면 좋은 자원"이 아니라
  **전선 지속력과 직결되는 자원**
- 보급대를 보호하는 것이 단순 힐 유닛 보호가 아니라
  전선 붕괴를 막는 핵심 전략이 됨

### 6-5-1. 웨이브 주기와 긴급 생성 아이템

- 기본 규칙:
  - **1분에 1웨이브**
  - 이 웨이브 주기는 모든 시대를 관통하는 공통 규칙
- 예외:
  - 게임 시작 직후
  - 시대 업그레이드 직후
  에는 **즉시 1웨이브 생성 아이템**이 1개 생김
- 이 아이템은 즉시 써도 되고 보관 후 나중에 써도 됨
- 단, 아이템 사용 가능 조건:
  - **이전 웨이브가 생성된 후 10초가 지나야 사용 가능**

해석:

- 기본 템포는 1분 1웨이브로 안정적으로 유지
- 대신 초반 전개/시대 전환 타이밍에는
  **플레이어가 한 번 템포를 강제로 당길 수 있는 선택권**을 가짐
- 단, 이 수치는 **1:1 기준 기본값**임
- 3인/4인 플레이처럼 상대 수가 늘어나면
  - 생산 속도
  - 식량 소모량
  - 그 외 전선 유지 수치
  가 함께 증가해야 함

해석:

- 다인전은 단순히 적만 늘어나는 모드가 아니라
  **경제/생산 템포 자체가 스케일링되는 모드**로 봐야 함

### 6-5-2. 시대별 기본 웨이브 편성

- 기본적으로 **전투 미니언 5기 + 보급병 1기**
- 시대에 따라 5기의 조합만 달라짐
- 이벤트성 식량 버프가 있으면 이후 1~3웨이브 동안
  전투 미니언 1기가 추가될 수 있음

초안 편성:

- 석기 시대:
  - 돌 투석병 2
  - 돌도끼병 3
- 청동기:
  - 돌 투석병 2
  - 청동검병 2
  - 청동창병 1
- 초기 철기:
  - 돌 투석병 1
  - 활 1
  - 청동검병 1
  - 철검병 1
  - 철창병 1
- 중기 철기:
  - 활 2
  - 철검병 2
  - 철창병 1
- 후기 철기:
  - 활 1
  - 머스킷 1
  - 철검병 1
  - 기사 1
  - 철창병 1

주의:

- 여기서 후기 철기는 "강철 시대"가 아니라
  **중세 끝무렵 단계**를 뜻함

### 6-5-3. 시대별 기본 식량 소모와 추가 병력 소모

- 초기에는 **웨이브 1개 출발당 식량 5 소모**
- 시대가 올라갈수록 웨이브 기본 식량 소모량도 조금씩 증가
- 예시:
  - 후기 철기 기본 웨이브는 식량 20 소모
- 특정 연구/업적에 의해 몇 웨이브 동안 병력이 추가될 수 있음
- 이때 추가 병력 1기당:
  - **그 시대 기본 추가값 x 2** 만큼 식량을 더 소모
- 예시:
  - 후기 철기에서 `기사 +1, 3웨이브` 효과를 켜면
  - 기본 식량 20에 더해
  - 후기 철기 추가 단가 4의 2배인 **8**이 추가 소모

### 6-5-4. 식량 자연 회복과 식량 종사 일꾼

- 기본적으로 식량은 **1초당 1** 회복
- 추가로 식량 종사 일꾼을 배치하면 시대에 따라 보너스 생산
- 식량 종사 일꾼 1기당 추가 생산:
  - 석기 시대: 5초당 1
  - 청동기 시대: 4초당 1
  - 초기 철기: 3초당 1
  - 중기 철기: 2초당 1
  - 후기 철기: 1초당 1

### 6-5-5. 식량 부족 시 웨이브 실패

- 식량이 부족하면 웨이브가 출발하지 못할 수 있음
- 초안 처리:
  - 일단은 **실패 메시지만 표시**
- 향후:
  - 웨이브 시도 실패 페널티 추가 예정
  - 단, 구체 페널티는 아직 미정

### 6-5-6. 다인전 스케일링 원칙

- 지금까지 적어 둔 웨이브/식량/생산 수치는 **모두 1:1 기본 기준값**
- 상대가 2명 이상이 되면 아래 수치들은 함께 스케일링 대상:
  - 웨이브 생산 압력
  - 식량 소모량
  - 필요 자원량
  - 필요 생산량
- 스케일링 방향은 **상대 수 비례형**으로 고정
- 즉, 시스템 구조상 `opponentCount`를 기준으로
  웨이브 압력과 유지 비용이 함께 증가하는 방식이 맞음

초안 해석:

- 1:1은 기준값
- 적이 2명인 3인전은 기준보다 더 높은 생산/소모 압력
- 적이 3명인 4인전은 그보다 더 높은 압력

정확한 배수표는 별도 확정 필요

### 6-5-7. 적 미니언 처치 금 보상

- 적 미니언을 처치하면 **소량의 금**을 얻음
- 석기 시대 기준 기본 보상 감각:
  - **1기당 금 1**
- 이후에는 시대와 병종에 따라 조금씩 증가

의미:

- 수비를 잘해도 최소한의 경제 보상이 들어와야
  밀리는 쪽도 역전 발판이 생김
- 킬 골드는 공격/수비 모두에 경제적 의미를 부여함

### 6-6. 연구 일꾼 규칙

- 일반 일꾼과 별도로 **연구 일꾼**이 존재
- 연구 일꾼 1명을 직접 고용하려면:
  - 일반 일꾼 1명 가격의 5배
  - 추가로 금속 50
- 또는:
  - 기존 일반 일꾼 10명을 제거하고 연구 일꾼 1명으로 전환 가능

해석:

- 연구 일꾼은 단순 상위 일꾼이 아니라
  **경제 인구를 연구 속도로 전환하는 선택지**
- 즉, 플레이어는
  - 생산/자원 수급
  - 전선 유지
  - 연구 가속
  중 어디에 인구를 태울지 판단해야 함

## 내부 구현을 어떻게 갈아엎어야 하나

아래는 **지금 코드 기준 실제 변경 단위**다.

### 1. 맵 시스템 교체

현재:

- `generateDungeon()` 기반 랜덤 던전

필요:

- 고정형 또는 시드형 **대칭 레인 전장 생성기**
- 2인/4인 모드에 따라 다른 레이아웃 지원
- 요소:
  - 본진
  - 레인
  - 교차 광장
  - 거점
  - 건설 가능 구역

추천 새 파일:

- `src/systems/battlefieldGenerator.ts`
- `src/data/maps.ts`

### 2. 스쿼드 시스템 재구성

현재:

- 리더 + 추종 병사 + 개별 HP/XP

필요:

- 고용 병력 목록
- 병종별 비용 / 유지비 / 전선 배치 상태
- 자동 스폰 또는 리더 동행 병력의 구분
- 병력 소속, 레인 배치, 목적지 상태

추천 방향:

- `Squad`를 유지보수하기보다 `ArmySystem`으로 교체하는 편이 깔끔함.

### 3. 경제 시스템 신설

필수 새 시스템:

- `gold`
- `income per tick`
- `wage per tick`
- `capture income`
- `tech cost`
- `build cost`
- `recruit cost`

추천 새 파일:

- `src/systems/economy.ts`

### 4. 기술 트리 시스템 신설

필수 기능:

- 연구 가능한 항목 데이터
- 선행 조건
- 연구 시간 또는 즉시 구매 여부
- 연구 결과:
  - 병종 해금
  - 능력치 업그레이드
  - 구조물 해금
  - 경제 보너스

추천 새 파일:

- `src/systems/research.ts`

### 5. 구조물/거점 시스템 신설

필수 기능:

- 본진
- 거점
- 요새
- 화살탑
- 보급소
- 파괴/점령 상태

추천 새 파일:

- `src/data/structures.ts`
- `src/systems/structures.ts`

### 6. 전투 시스템 단순화 + 대규모 유닛 대응

현재 전투는 소수 정예 스쿼드 기준이다. 새 게임은 병력이 더 많아질 수 있으므로:

- 개별 유닛 고급 AI보다
- **레인 이동 + 근거리 충돌 + 간단 표적 선택 + 집단 DPS 계산**
  쪽이 더 적합할 가능성이 크다.

중요:

- 모바일에서 다수 유닛을 안정적으로 돌리려면
  "정교한 1:1 액션 전투"보다
  **간결한 시뮬레이션형 전투**가 성능과 가독성에 유리하다.

### 7. UI 재설계

현재 UI는 "스킬 슬롯 + 인벤토리"다.

새 UI는 아래처럼 바뀌어야 한다:

- 좌측 또는 하단:
  - 금
  - 수입
  - 유지비
  - 인구/병력 수
- 우측 패널:
  - 생산/편성 탭
  - 건설 탭
  - 연구 탭
  - 산업/인구 탭
- 본진 광장 패널:
  - 시대 진입 상태
  - 인구 배치
  - 연구소/산업시설 현황
- 레인/거점 상호작용 패널:
  - 건설 가능 슬롯
  - 업그레이드 경로
  - 자원 요구량
- 미니언 편성 패널:
  - 현재 자동 생산 조합
  - 시대 전환 잠금 타이머

## 다음 상담에서 꼭 결정해야 할 질문

1. 자동 생산 미니언의 **초기 조합 슬롯 수**
2. 시대 전환 후 **구시대/신시대 혼합 허용 시간 n분**
3. 거점 종류를 MVP에서 몇 개로 자를지
4. 1:1 / 3인 / 4인 기준 **상대 수 비례 배수표**를 어떻게 둘지
5. 연구소 자동 보급 범위를 어디까지 허용할지
6. 기술 업그레이드는 즉시 구매식인지, 연구 시간 방식인지
7. 초반 MVP 승리 조건은 본진 파괴 하나로 충분한지

위 목록 중 **세부 수치/배수/기본 비용**은 더 이상 전부 사용자 승인 대상으로
잡지 않는다. 큰 규칙이 이미 맞으면, 초기 밸런스값은 에이전트가 합리적 기본안으로
정하고 실제 구현/테스트를 우선 진행한 뒤 피드백으로 다시 조정한다.
