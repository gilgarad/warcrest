# Unit Asset Audit Checklist

이 문서는 2026-08-05 기준 `유닛 방향/포즈 샌드박스`와 실제 전장 렌더링이
같은 production 자산을 쓰는 전제에서, 캐릭터 자산을 전수 검수할 때 쓰는
고정 체크리스트다.

목표:

- 사람형 / 기병형 / 포병·차량형 / 보급형을 **빠짐없이 전수 검사**한다.
- "몇 장 보고 추정"이 아니라, **자동 geometry 감사 + 샌드박스 육안 확인**을
  둘 다 통과해야 완료로 본다.
- 문제를 고칠 때는 개별 땜질이 아니라, 먼저 실패 항목을 기록하고 그 항목이
  재검사에서 사라졌는지 확인한다.

## 전제

- `?sandbox=1`에서 보이는 캐릭터는 별도 데모용이 아니라 실제 게임과 같은
  production PNG / registry / presentation 규칙을 쓴다.
- 따라서 샌드박스에서 잘린 자산, 크기 점프, 방향 불일치가 보이면 실제
  게임도 같은 문제를 가진다.

## 검사 순서

1. geometry 감사 스크립트 실행
2. 그룹별 contact sheet / sandbox 캡처 생성
3. 사람형 전수 검사
4. 기병형 전수 검사
5. 포병·차량형 전수 검사
6. 보급형 전수 검사
7. 수정 후 1~6 반복

## 공통 Pass/Fail 항목

### 1. 잘림

- 무릎, 정강이, 발목, 군화, 말 다리, 바퀴, 포신, 머리, 투구, 창 끝이
  잘리지 않는다.
- 바닥 아래쪽이 사라져 보이거나, 프레임 경계에 몸 일부가 닿아 끊기면 fail.
- 포즈 전환 시에만 일부가 사라지면 그것도 fail.

### 2. 크기 일관성

- 같은 분류 안에서 체격이 갑자기 작거나 크지 않다.
- 같은 유닛의 `idle / walk-a / walk-b / attack` 사이에서 크기 점프가 크지
  않다.
- 공격 시 커지거나 작아지는 현상은 fail.

### 3. 방향 일관성

- 총구/시선/몸통이 서로 다른 방향을 보지 않는다.
- walk에서 idle과 정반대 방향으로 뒤집히면 fail.
- 좌우 미러링이 아니라, 원화 자체가 엉뚱한 방향이면 fail.

### 4. 걷기 포즈 자연스러움

- walk-a / walk-b가 실제 보행 리듬으로 읽혀야 한다.
- idle과 거의 같은 프레임이면 fail.
- 다리 교차, 발 디딤, 몸중심 이동이 전혀 안 보이면 fail.

### 5. 잔여물 / 부유 조각

- 발 아래 갈색 띠, 건초, 잘린 무기 조각, 공중에 뜬 파편이 없어야 한다.
- 본체와 무관한 저알파 debris가 남아 있으면 fail.

## 분류별 추가 항목

### 사람형

- 발끝이 ground ring 아래로 묻히지 않는가
- 상체/하체가 분리되어 다른 위치에 뜨지 않는가
- 총구 방향이 idle/walk에서 일관적인가

### 기병형

- 말 머리/다리/꼬리, 기수 상체, 창 끝이 전부 보이는가
- 말과 기수 비율이 기병끼리 크게 다르지 않은가
- walk에서 말이 단순 확대/축소처럼 튀지 않는가

### 포병·차량형

- 바퀴 아래 반쪽 잘림이 없는가
- 포신, 승무원, 차체가 포즈마다 크게 튀지 않는가
- 하단 debris 제거 후에도 차체가 정상 비율인가

### 보급형

- 발목 아래가 잘리지 않는가
- heal/support 포즈가 기존 컨셉(손을 들고 효과를 내는 동작)에 맞는가
- 대각 방향에서 몸 전체가 기울어 비정상적으로 보이지 않는가

## 실행 산출물

- geometry 감사 markdown / json
- production contact sheet
- sandbox contact sheet
- 수정 후 재검사 산출물

## 완료 기준

- geometry 감사에서 치명 플래그 없음
- 샌드박스 전수 검사에서 fail 없음
- 실제 전장에서도 동일 자산으로 확인
- `npm run build`, `npm test` 통과
