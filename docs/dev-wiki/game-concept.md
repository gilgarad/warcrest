# 게임 컨셉: 갈림길 정찰대 (가제)

NHN `nan2026` AI 게임잼 제출용 컨셉 문서. 2026-07-23 세션에서 사용자와
상의해 확정. 확정된 항목은 "결정됨", 아직 흔들릴 수 있는 항목은
"가안"으로 표시.

## 한 줄 소개

디아블로류 던전 안을 실제로 이동하며(3인칭, 안개 시야+미니맵) 적과
부딪혀 전투하고, 감옥에 갇힌 동료를 직접 찾아가 구출해 대열을 늘리는
실시간 던전 탐험 액션. 전투는 파타퐁식 커맨드로 처리.

## ⚠️ 방향 정정 (2026-07-23)

첫 구현은 갈림길을 "왼쪽 길/오른쪽 길" 버튼 메뉴로 추상화한 로그라이트
카드 게임이었는데, 이는 사용자가 원래 예시로 든 "디아블로 던전에서
실제로 움직이며 적을 죽이고 동료를 구출" 이미지와 어긋났다. 사용자
피드백을 받고 즉시 방향을 바로잡음: 아래 내용은 정정된 최종 방향이고,
메뉴 기반 버전은 폐기(`docs/dev-wiki/log.md` "MVP 첫 구현"/"던전 탐험형
재설계" 항목 참고).

## 장르/분위기 (결정됨)

- 순발력 승부가 아니라 "잠깐 멈춰 생각하는" 페이스 — 다만 이동 자체는
  실시간(화살표/WASD), 메뉴 클릭이 아님.
- 로그라이트: 던전 하나가 3~5분 분량, 매 판 절차적으로 새로 생성됨 →
  재도전 유도, 짧은 세션에도 심사위원이 여러 판 돌려볼 수 있음.

## 핵심 루프 (구현됨, 세부는 프로토타입하며 다듬을 것)

1. 탑다운 2D, 캐릭터 주변만 보이는 제한 시야(안개) + 화면 우상단
   미니맵 — 디아블로 던전 진입 레퍼런스 그대로.
2. 방향키/WASD로 병사를 실시간 이동. 절차적으로 생성된 통로+갈림길을
   실제로 걸어서 탐색.
3. 던전 안에 배치된 적/포로에게 다가가면: 적은 접촉 시 전투 발동,
   포로는 접촉 시 자동 구출(대열 합류) — 메뉴 클릭이 아니라 이동 자체가
   상호작용.
4. 승리: 미션 지점(깃발) 타일에 도달. 패배: 대열 전멸(전투 패배로
   마지막 대열원까지 잃으면).

## 전투 시스템 — 파타퐁식 커맨드 (결정됨, 세부 가안)

- 비주얼보다 **플로우**가 핵심: 여러 병종이 섞인 대열이 만드는 커맨드
  조합이 재미의 본체.
- 적과 부딪히면(던전 안에서 실제로 접촉) 이동이 멈추고, 화면 오른쪽에
  **항상 떠있는** 공격/방어 슬롯 패널이 활성화되며 타이머 바가 빠르게
  줄어듦(정밀 리듬 판정이 아니라 "빨리 판단해서 누르기"에 가까운
  긴장감). 처음엔 화면 가운데 팝업 박스로 만들었다가 "박스가 생기는 게
  아니라 오른쪽 슬롯" 이라는 사용자 피드백으로 2026-07-23에 상시 패널로
  교체 — `docs/dev-wiki/log.md` "비주얼/전투 UI 정정" 항목 참고.
- 플레이어는 미리 쌓아둔 공격/방어 "덱"에서 타이밍에 맞는 커맨드를
  선택해 입력 — 어떤 커맨드가 가능한지는 현재 대열의 병종 구성에 따라
  달라짐.
- MVP 단순화 후보: 적 유형별로 필요한 커맨드 아이콘이 뜨고, 타이머가
  0이 되기 전에 맞는 병종 커맨드를 순서대로 눌러 처리 — 정밀 리듬 게임이
  아니라 큐 소진형 판단 게임으로 구현.

## 대열(스쿼드) 시스템 (결정됨)

- 포로를 구출할수록 뒤에 병사가 줄줄이 붙음(비주얼 임팩트).
- 전투에서 맞으면 앞줄부터 하나씩 손실 — 스네이크처럼 대열이 늘고 줆.
- 병종이 섞일수록 전투 커맨드 덱의 폭이 넓어짐(위 전투 시스템과 연결).

## 아트 스타일 (결정됨, 2026-07-23 톤 정정)

- AI 생성 픽셀아트가 원안이었으나, 이 환경에 이미지 생성 도구가 없어
  Phaser Graphics로 직접 그리는 벡터 기반 "가분수" 캐릭터로 대체 중
  (`src/gfx/chibi.ts`). 저작권 이슈는 이 방식이 오히려 원천 차단.
- 첫 던전 버전을 본 사용자가 "80년대 게임 같다"며 최소 2000년대 초반
  수준의 유사-3D 톤을 요구. 실제 3D 렌더링 없이 다음으로 대응:
  캐릭터에 하이라이트/셰도우+아웃라인(`shade()` 헬퍼), 벽은 통로에 접한
  면만 밝은 윗면+어두운 정면으로 입체 블록처럼 보이게, 바닥은 벽에 붙은
  타일에 그림자를 드리워 벽 높이감을 만듦(개별 타일마다 명암을 넣는
  방식은 줄무늬처럼 보여서 폐기, `docs/patterns/README.md` 참고).

## 카메라/스케일 (결정됨, 2026-07-23)

- 첫 던전 버전은 시야가 너무 좁고 캐릭터가 화면에 비해 컸음 → 타일을
  작게(20px→13px), 시야 반경을 넓게(4→9칸), 던전 자체도 더 크게
  키워서 "더 뒤에서 본 것처럼 훨씬 넓은 범위"가 보이도록 조정.
  캐릭터 텍스처도 별도의 작은 사이즈(`chibi-*-sm`)로 다시 그림.

## 임팩트 포인트 / 플랫폼 (결정됨)

- 이번 제출에서 보여줄 임팩트는 **완성도/폴리싱** — 화려한 스코프
  확장보다 하나를 끝까지 다듬는 쪽.
- 플랫폼은 **웹만** — 브라우저 실행, GitHub Pages 배포 후보.

## 스코프 리스크 (에이전트 메모, 사용자에게 플래그함)

로그라이트 절차 생성 + 파타퐁식 커맨드 전투 + 대열 관리 + AI 생성
픽셀아트 조합은 잼 스코프치고 요소가 많음. "완성도" 임팩트를 노린다면
MVP를 아래 순서로 좁혀 먼저 완결시키고, 남는 시간에 넓히는 게 안전:

1. ✅ 실시간 이동 던전 + 단일 전투 인카운터(커맨드 1종) + 구출 접촉 —
   2026-07-23 구현·검증 완료. 첫 시도(메뉴 기반)는 폐기하고 던전 탐험형
   으로 재설계, `docs/dev-wiki/log.md`의 "던전 탐험형 재설계" 항목 참고.
2. ✅ 대열 증감(구출/손실), 안개 시야, 미니맵 — 같은 구현에 포함됨.
3. 병종 다양화로 커맨드 덱 폭 넓히기 — 아직 미착수, 사용자가 의도적으로
   다음으로 미룸("일단 끝까지 해서 화면 보면서 지시").
4. 던전 생성 난이도 곡선(방 개수/분기 조절), 아트 폴리싱 — 미착수.

아트는 AI 이미지 생성 도구가 이 환경에 없어서, 실제 픽셀아트 대신
`src/gfx/chibi.ts`가 Phaser Graphics로 직접 그리는 벡터 기반 "가분수"
캐릭터로 대체 중. 나중에 실제 이미지를 구하면 텍스처 키만 바꿔 끼우면
되도록 렌더링 로직과 분리되어 있음.
