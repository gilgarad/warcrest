# Codex 프롬프트 엔지니어링 로그

**이 세션(Claude Code)의 역할이 바뀌었다 (2026-07-27부터, 별도 지시 전까지 유지).**
더 이상 이 저장소의 소스 코드를 직접 작성/수정하지 않는다. 대신:

- 사용자가 다른(Codex) 세션에서 진행 중인 작업 상태나 "뭐가 안 됨/이상함" 같은
  추상적인 피드백을 말로 전달하면,
- 이 세션은 저장소의 **현재 실제 코드 상태를 계속 추적**해서 그 피드백을
  구체적인 파일/증상에 근거를 붙이고,
- Codex 세션에 그대로 붙여넣을 수 있는 **완성된 프롬프트**를 작성해 응답한다.

`docs/ai-usage/session-log.md`(매 턴 AI 활용 요약, 대회 제출용)와는
**별개 문서**다 — 이 로그는 "무슨 프롬프트를 왜 만들었는지"의 기록이고,
저 로그는 이 저장소에 대한 AI 협업 전체 서사다. 하네스의 다른 규칙
(`docs/dev-wiki/contract.md`의 The One Rule / backlog.md 등)은 그대로
유지된다 — 이 세션이 실제로 파일을 바꾸는 일은 없겠지만, 만약 바뀐다면
그 규칙을 따른다.

## 형식

턴마다:
- **사용자 상황/요청 원문 요약** (가능하면 원문 인용 포함)
- **확인한 현재 코드 상태** (파일/커밋/증상 근거)
- **작성한 프롬프트** (전체 텍스트, Codex에 그대로 붙여넣을 수 있는 형태)

## 2026-07-27 (1) — 모드 전환 + 현재 상태 재확인

- **사용자 지시 요약**: 이 세션은 이제부터 프롬프트 엔지니어링 전용으로
  전환. 하네스(백로그 등)는 유지하되, 대화 요약 저장은 이 별도 문서로
  옮길 것. 사용자가 앞으로 추상적인 문제 상황("뭐가 안 됨", "뭐가
  이상함")을 말하면, 이 세션이 현재 소스 상태를 근거로 Codex용 프롬프트를
  작성. 별도 지시 전까지 이 모드 유지. 먼저 그동안 추가 개발된 내용을
  확인해달라고 요청.
- **확인한 현재 코드 상태** (2026-07-27, 브랜치 `terrain-prototype-central`,
  최신 커밋 `91fb6c0`):
  - 오디오: 이전 턴에 만든 독립 프로토타입(`f57303b`)이 Codex 세션에
    의해 실제 게임에 완전히 통합됨(`docs/dev-wiki/audio-integration-validation.md`).
    `BootScene`이 `getAudioSystem()` 싱글턴을 초기화, Boot=menu/
    시작=preparation/웨이브=battle-low/전투 강도에 따라 battle-high
    (엔게이지 유닛≥6 또는 발사체≥3 또는 최근 공격≥7 시 진입, 최소
    6초 유지, engaged≤2 & 발사체=0 & 공격≤1일 때만 저강도 복귀 —
    히스테리시스로 전투 판정에 영향 안 줌), 요새 체력 35% 이하에서
    경고 레이어(1.8초, 12초 쿨다운), 승패에 따라 victory/defeat,
    재시작 시 director reset. SFX 32종 중 고빈도(근접/원거리/피격/사망/
    타워)는 실제 전투 이벤트에 연결됨(reduced 모드가 기본, 고빈도
    요청 1/3만 샘플링). 공간 음향(`spatialAudio.ts`, 카메라 상대
    거리 기반 볼륨+팬)도 추가됨. 설정 패널(`src/ui/AudioSettingsPanel.ts`,
    HUD "소리" 버튼 또는 Esc)도 신규. 여전히 실제 오디오 파일은
    0개(전부 `missingAsset: true`, 합성 음으로 대체) — 이 부분은
    내가 처음 설계한 그대로 유지됨.
  - 비주얼/유닛: 최신 커밋(`91fb6c0`, "improve unit readability and
    fortress point rules")으로 유닛 크기 프리셋이 `compact/recommended/
    large` 3종으로 확정되고 `recommended`가 기본값. 타워 높이(일반
    144px/고정 요새 162px), 이동 방향에 따른 좌우 반전, 공격 시 방향
    잠금, 고정 요새 UI 규칙(만피 시 조작 없음/피해 시 수리만/파괴 시
    재건만, 해체·용도변경 불가), 일반 거점 UI(소유 시 요새/보급/조달
    선택+해체) 등이 `docs/dev-wiki/terrain-prototype-v3-validation.md`에
    상세 기록됨.
  - 지형: V1→V2→V3까지 반복. V2는 중앙 거점 원형 패드만 불투명 도로

    맵으로 확장하지 않고 유닛 크기/타워 높이/방향/공격 표현/고정
    요새 규칙만 추가 검증(`terrain-prototype-v3-validation.md`). 즉
    **중앙 거점 지형 개선은 아직 전체 레인에 적용 안 됨** — 여전히
    사용자 판단 대기 중인 항목으로 보임.
  - `project_development.md`(단일 현황판)는 **갱신이 안 돼서 stale함**
    — 여전히 `DungeonScene`/필드 자동전투를 "현재 상태"로 기술하고
    있고, 오디오 통합이나 유닛 가독성 커밋, terrain v3는 전혀 반영 안 됨.
    다음에 Codex 쪽에 문서 정리를 지시할 기회가 있으면 이 부분도
    언급할 것.
